# 数据采集与口径

## 先读这段：数据源是硬依赖

这套方法论不产出数据，只产出判断。**数据从哪来，决定结论能到哪。**

没有数据源时，最坏的结果不是"分析不出来"，而是 Agent 用训练记忆里的旧数字编出一份看起来完整的报告——销量、CPC、评论数都有，但全是幻觉。这种报告比不做更危险。

所以本文件规定三件事：

1. **数据源怎么接**（三条路线，从全自动到纯手工）
2. **每个字段缺了会怎样**（降级决策表——这是本文件最重要的部分）
3. **缺数据时怎么执行**（不编数字，只输出待补证清单）

**核心原则：成本类字段缺失，结论止步于"待补证"；需求类字段缺失，结论可以到"允许测款"但要标注精度损失。** 把这两类混为一谈，就会做出"看起来数据齐全、实际结论为空"的报告。

## 数据源接入：三条路线

### 路线一：类目洞察 MCP（字段最全，推荐）

参考实现是**西柚找词**（xiyou-insight），它把本方法论需要的字段基本做全了：类目榜单、ASIN 详情（含真实 FBA 费与包装尺寸）、销量估算、流量结构、关键词指标、ABA 趋势。本仓库的 `工具映射` 表就是按它的接口写的。

- 官网与申请入口：**https://platform.xydc.com/**
- MCP 端点：`https://mcp.xydc.com/mcp`
- 认证方式：在你自己的账号后台生成 Bearer Token，填进 Agent 的 MCP 配置

```json
{
  "mcpServers": {
    "xydc-mcp": {
      "url": "https://mcp.xydc.com/mcp",
      "headers": { "Authorization": "Bearer <你的令牌>" }
    }
  }
}
```

三点必须说清楚：

- **按查询额度计费（Credits），不是免费的。** 类目资源生成等接口单次消耗较高，具体额度与价格以官网为准。这是它的成本，不是本仓库的成本。
- **本仓库与西柚找词无隶属、无返佣、无合作关系。** 列出它只是因为字段最贴合，不是唯一选择。
- **工具名基于 `xiyou-insight` v1 接口**。厂商改接口后技能可能失效，届时以实际 `tools/list` 返回为准，不要按本文档硬编码。

### 路线二：你已有的商业选品工具

如果你已经有卖家精灵、Helium 10、Jungle Scout、Keepa、Sorftime 的账号，不需要再买一套。这些工具能覆盖"销量估算 + 关键词 + 上架时间"，缺的只是**真实 FBA 费与包装尺寸**——这个从亚马逊官方费率表手查更快：

- FBA 费率表：搜 `Amazon FBA fulfillment fees` 官方页面，按尺寸分段查
- 佣金表：搜 `Amazon referral fee` 官方页面，按类目查
- 评论原文：直接读商品页，不要用工具的"AI 总结"

把这些数据填进报告的"数据来源"栏，可信度标 B 级（工具估算）或 A 级（官方费率）。

### 路线三：零成本手工模式

一个品、一次判断，完全不需要付费工具：

| 字段 | 手工获取方式 | 可信度 |
|---|---|---|
| FBA 配送费 | 官方费率表按尺寸分段查；或 FBA 收入计算器 | A |
| 佣金 | 官方类目佣金表 | A |
| 包装尺寸重量 | 商品页 `Product information` 栏，或向供应商要装箱单 | A |
| 落地成本 | 1688 / 阿里询价，含包装与头程 | A |
| 销量量级 | 商品页 `bought in past month` 标签 + 评论增速（月新增评论 ÷ 留评率约 1–3%） | C |
| 关键词搜索量 | 品牌备案后的 ABA 免费版；或前台搜索下拉词判断词序 | C |
| 上架时间 | 商品页 `Date First Available` | A |
| 评论痛点 | 手动读 1–3 星评论原文，摘 10 条以上 | A |

手工模式慢，但**结论的可信度不比付费工具低**——因为最关键的 FBA 与落地成本本来就是 A 级数据，工具给不了。工具真正买的是"批量"和"快"。

## 字段需求清单与降级决策

这张表是本文件的判断核心。取数前先对照，缺哪个字段就锁定结论上限。

| 字段 | 用在哪一步 | 缺失时结论上限 | 替代来源 |
|---|---|---|---|
| **FBA 配送费 + 包装尺寸** | 第三步 毛利 | **待补证**（不得测款） | 官方费率表 + 商品页尺寸 |
| **落地成本** | 第三步 毛利 | **待补证**（不得测款） | 供应商报价 |
| **类目佣金比例** | 第三步 毛利 | **待补证** | 官方佣金表（多数 15%，珠宝/电子配件例外） |
| **产品安全属性**（年龄、小零件、电池、食品接触） | 第一步 合规 | **待补证** | 供应商 + 样品实测 |
| **权利状态**（外观专利、商标、IP 授权） | 第一步 合规 | **待补证** | 专利检索 + 商标库 |
| 销量估算 | 第二步 需求 | 允许测款（标精度损失） | Keepa / BSR + 评论增速 |
| 关键词搜索量 | 第二步 需求 | 允许测款（标精度损失） | ABA 免费版 / 搜索建议 |
| 广告流量占比 / CPC | 第四步 测款参数 | 允许测款（CPC 用类目均值估） | 广告后台建议竞价 |
| 上架时间 / 新品存活 | 第二步 竞争判断 | 允许测款 | 商品页 Date First Available |
| 评论原文 | 差异化设计 | 允许测款（差异化假设未证实） | 手动读评论 |
| 5 年趋势 / 季节性 | 排序参考 | 不影响结论 | — |

**读法**：前三行是"缺了就不能给结论"，后面是"缺了可以给结论但要降精度"。具体到执行上：

> 只有 FBA 费 + 落地成本 + 佣金三项齐全，才能算出真实的广告前毛利，才能说"允许测款"。
> 这三项缺任何一项，无论竞品销量多好看，结论都是"待补证"。

## 数据源分层

| 层级 | 来源 | 用途 | 可信度 |
|---|---|---|---|
| A 级 | 亚马逊官方费率表、FBA 计算器、ABA 品牌分析、商机探测器、评论原文、证书/专利文件 | 成本、需求、权利状态 | 已核实 |
| B 级 | 第三方工具（卖家精灵、Helium 10、Jungle Scout、Keepa、Sorftime）、类目洞察 MCP | 销量估算、流量结构、CPC、竞争密度 | 工具估算 |
| C 级 | 未取得的数据 | — | 显式标"待补证" |

**原始资料真实，不代表据此作出的判断已经证实。** 官方费表可信，但选错包装档位测算仍会错；证书可查，不代表覆盖你的材料、工厂和使用方式。

## 无数据源时的执行剧本

如果用户什么都没接，不要硬跑五步，按这个顺序做：

1. **宣明限制**：一句话说明"当前无类目数据源，本次只能做成本侧判断，需求侧标待补证"。不要沉默地降级。
2. **先要三个数**：目标售价、FBA 费（或包装尺寸让我推）、落地成本。这三个数用户一定拿得到，拿到就能算硬门槛。
3. **算价格下限**，直接给结论：这个价格能不能撑住 30%。这一步不需要任何付费数据，却能回答用户 80% 的问题。
4. **需求侧只写清单不写数字**：列出需要验证什么（搜索量、头部评论壁垒、新品存活），标 C 级待补，不填估算值。
5. **给出获取路径**：告诉用户这三个数从哪拿、大概多久。

宁可交一份"成本算得死、需求待补证"的短报告，也不要交一份"数据填得满、全是编的"长报告。

下表是**路线一（西柚找词 xiyou-insight）**的具体接口，其他数据源请按字段需求对照替换。未接入时可用店铺页抓取 + 亚马逊前台数据替代，但销量与流量只能标 B 级。

## 关键参数经验

- **categoryId 与 resourceId 必须配对复用**。类目洞察类接口通常要求先 `generate_category_insight_resource` 生成 resourceId，同一次调研内所有类目查询复用同一个；重复生成会重复扣额度。
- **`get_category_sales_ranking` 的 query 参数是最有用的功能**。它按标题词筛选，能直接回答"某个主题在类目内有多少在售 ASIN、头部多少销量"，是类目扫描与主题筛选的核心手段。
- **`reportPeriod` 选 `last30days`**，与关键词周数据对齐时注意窗口差异（销量 30 天，关键词 1 周）。

## 返回体处理（重要）

类目榜单接口单次返回常有 100K–300K 字符，直接读会超限。处理方式：

1. 把结果落盘为文件（工具结果目录下会保留原始文件）
2. 用 Python 读取 JSON，只提取需要的字段
3. 不要试图在对话里浏览原始返回

解析模板：

```python
import json
d = json.load(open(path, encoding='utf-8'))['data']
L, total = d['list'], d['total']
f = lambda x: float(x) if x not in (None, '') else 0.0

sales  = [it['metrics']['sales']['value'] or 0 for it in L]
price  = [f(it['asinInfo']['priceDistribution'].get('value')) for it in L]
rating = [it['asinInfo'].get('ratings') or 0 for it in L]
days   = [it['asinInfo'].get('listedDays') or 99999 for it in L]
brand  = [it['asinInfo'].get('brand') for it in L]
```

## 字段陷阱

| 陷阱 | 说明 | 正确做法 |
|---|---|---|
| **店铺页价格是当地币种** | 抓取卖家店铺页时，价格可能按汇率显示为 CNY（如 `CNY 106.67`），不是美元 | 价格一律从 `get_asin_info` 取；抓取页只用于拿 ASIN 清单与标题 |
| **`size.package` / `weight.package` 可能是字符串** | 不是 dict，`.get()` 会报 AttributeError | 直接 `str(sz.get('package'))` 打印 |
| **销量是档位化的** | 返回 700 / 600 / 300 / 200 / 100 / 50 / 0 这类档位，不是精确值 | 报告中标"估算"，不要写成精确销量 |
| **评分归属** | 变体共享评分，子体评分数可能属于父体 | 记录评分口径，变体单独成表 |
| **`listedDays` 为 None** | 老品可能无上架天数 | 按 99999 处理，不要当成新品 |
| **`trafficScore.summary` 是流量结构** | 自然位/广告位占比只说明流量来源 | 不能直接推断销量来源 |
| **搜索量为 0** | 可能是无数据，不是无需求 | 标"无 ABA 数据"，与"需求为零"区分 |

## 口径规则

**销量与流量必须分开记录。** 排名、流量估算、销量估算分别记录，不能互相替代。自然位占比高说明流量结构健康，不代表卖得好；转化才是销量的直接前提。

**父子变体不平摊。** 父体销量不能平均分配给子体，各子体需分别估销。同一父体下多个颜色不能当作多个独立品牌来统计集中度。

**关键词按购买意图聚类。** 同一购买意图的词归为一组，不能把多个词的搜索量直接相加当作独立买家数——同一买家会用多个词，相加会重复计算需求。

**ABA 排名不是搜索量。** 排名是相对位置，不能当绝对需求量用。

**Google Trends 只说明趋势不说明销量。** "bow cake" 的热度不能直接当作某款缎带插牌的销量依据；区分"广泛审美趋势"与"具体购买需求"。

**主题大词与品类精准词是两回事。** 主题派对词（如 `dinosaur birthday decorations`）通常是主题插牌词的 5–10 倍。主题派对词流量大但竞争激烈、CPC 高；精准词流量小但转化高、CPC 低 30–50%。判断进入策略时必须两个都取。

## 店铺页抓取（无 MCP 时的替代）

卖家店铺页可直接抓取 ASIN 清单，用于反向拆解某个卖家的产品线：

```bash
curl -sL --compressed \
  -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/126.0.0.0 Safari/537.36" \
  -H "Accept-Language: en-US,en;q=0.9" \
  "https://www.amazon.com/s?me=<SELLER_ID>&marketplaceID=ATVPDKIKX0DER" \
  -o seller.html --max-time 45
```

要点：必须带浏览器 UA 与 `--compressed`；需分页或用 `&page=2` 取全量。通用网页抓取工具常被 Amazon 拦截（503），curl 直取成功率更高。

抓到后提取 `data-asin` 与标题，再用 `get_asin_info` 补齐真实价格、FBA 费、尺寸重量、上架时间。
